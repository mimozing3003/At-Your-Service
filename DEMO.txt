COMMON Q&A (PREPARATION)
═══════════════════════════════════════════════════════════════

Q: "Does this use GPT or paid APIs?"
A: "No! 100% free. Rule-based AI with regex parsing and weighted 
    scoring. Optional LLM hooks are commented out behind env flags."

Q: "How does offline mode work?"
A: "30 services pre-seeded in JSON. If external APIs fail (Nominatim,
    Overpass, AI engine), we fall back to local data immediately."

Q: "How do you ensure AI explainability?"
A: "Every score has a transparent formula. We show exact weights:
    45% rating, 25% price, 20% distance, 10% sentiment. Users see
    the breakdown on demand."

Q: "What about production deployment?"
A: "Backend → Render/Railway, Frontend → Vercel, AI → HF Space or 
    Render, DB → MongoDB Atlas free tier. All documented in README."

Q: "How long did this take to build?"
A: "Core backend + AI engine: ~2 days. Frontend: ~4 hours. 
    Completely production-ready with auth, validation, fallbacks."

Q: "Can I add my own services?"
A: "Yes! Provider onboarding form lets anyone register services.
    JWT-protected POST endpoint validates and stores in MongoDB."

Q: "Does it work on mobile?"
A: "Yes! Responsive Tailwind design. Loading screen, service cards,
    and all pages adapt to mobile screens."

═══════════════════════════════════════════════════════════════
TROUBLESHOOTING DURING DEMO
═══════════════════════════════════════════════════════════════

IF LOADING SCREEN DOESN'T SHOW:
→ Clear session storage (F12 → Application)
→ Hard refresh (Ctrl+Shift+R)

IF AI ENGINE FAILS:
→ Check http://localhost:8000/health
→ Restart: cd ai-engine && python app.py
→ Emphasize: "This is why we have offline fallback!"

IF MONGODB CONNECTION FAILS:
→ Restart MongoDB: net start MongoDB (Windows)
→ Or use Atlas connection string
→ Show: "Fallback to in-memory data for demo"

IF FRONTEND NOT LOADING:
→ Check npm run dev is running
→ Visit http://localhost:5173 directly
→ Clear browser cache
